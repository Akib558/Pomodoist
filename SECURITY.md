# Security Policy

## Supported versions

Security fixes target the latest stable release. Older releases do not have a
separate security maintenance commitment. Update to the latest release before
checking whether an issue still occurs. If you cannot safely update, report the
issue anyway and include the affected version.

## Reporting a vulnerability

Report suspected vulnerabilities privately to
[security@pomodoist.com](mailto:security@pomodoist.com). This includes issues in
Pomodoist clients, hosted services, self-hosted deployments, and integrations.
Do not disclose vulnerabilities in public issues or pull requests.

Include, where available:

- The affected component, version or commit, platform, and deployment type.
- A description of the vulnerability and its potential impact.
- Steps to reproduce it or a minimal proof of concept.
- Relevant logs or screenshots with credentials and personal data removed.

Never send passwords, access tokens, private keys, or another person's data.
Test only on accounts and systems you own or have permission to test.

Maintainers will use the email thread to clarify the report and coordinate a
fix and disclosure. Please allow time to investigate before publishing details.
Response and resolution times depend on severity and maintainer availability;
there is no guaranteed response deadline.

For ordinary bugs and feature requests, use the
[issue templates](https://github.com/Kabanya/Pomodoist/issues/new/choose).
